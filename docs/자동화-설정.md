# 수집 자동화 설정

`.github/workflows/collect.yml` — 매일 **한국시간 새벽 5시**(UTC 20:00)에 돌면서
서울 예약 데이터와 전국 표준데이터를 새로 받아 `site/data/`를 갱신하고 커밋한다.

서울 공공서비스예약이 하루 1회 갱신되므로 그 뒤에 돌도록 잡았다.

---

## 돌아가는 순서

```
1. 서울 공공서비스예약 수집      tools/collect_seoul.py     (SEOUL_KEY 필요)
2. 전국 표준데이터 수집          tools/collect_standard.py  (DATA_KEY 필요)
3. 서울만 병합·정규화·중복제거    tools/build_dataset.py
4. 변경분이 있으면 커밋 후 푸시
5. 실행 요약을 Actions 화면에 출력
```

## 필요한 준비 두 가지

### ① GitHub 저장소

아직 원격이 없다. 만들고 푸시해야 워크플로가 돈다.

```bash
cd ~/Desktop/클로드작업/moilgot
gh repo create moilgot --private --source=. --remote=origin --push
```

공개로 할 거면 `--private` 대신 `--public`.

### ② 시크릿 2개 등록

발급받아 두신 키를 저장소 시크릿으로 넣는다. **키 값은 화면에 남지 않게 대화형으로** 넣으시면 된다.

```bash
cd ~/Desktop/클로드작업/moilgot
gh secret set SEOUL_KEY
gh secret set DATA_KEY
```

각각 실행하면 값을 물어본다. 붙여넣고 엔터.
웹에서 하려면 저장소 → Settings → Secrets and variables → Actions → New repository secret.

## 현재 상태 (2026.9.1)

**스케줄은 꺼둔 상태다** (`disabled_manually`).
시크릿을 등록하기 전까지 매일 실패 알림이 오기 때문에 잠시 멈춰 두었다.
8/28~8/31 다섯 번의 실패는 모두 `SEOUL_KEY 시크릿이 없습니다`로, 첫 스텝에서 멈춘 것이다.
데이터가 망가진 적은 없다.

키를 넣고 다시 켜는 한 줄:

```bash
gh secret set SEOUL_KEY && gh secret set DATA_KEY && gh workflow enable "데이터 수집"
```

## 확인

등록 뒤 손으로 한 번 돌려본다.

```bash
gh workflow run "데이터 수집"
gh run watch
```

## 안전장치

`build_dataset.py`에 **기존 대비 70% 미만이면 중단**하는 장치가 있다.
API가 일시적으로 반쪽만 응답할 때 멀쩡한 데이터를 덮어쓰지 않기 위한 것이다.

의도적으로 범위를 줄인 경우(예: 필터를 좁힘)에는 비율을 낮춰 수동 실행한다.

```bash
gh workflow run "데이터 수집" -f min_ratio=0.3
```

## 왜 표준데이터도 매일 받나

표준데이터는 분기 갱신이라 매일 받을 필요는 없다. 다만 호출이 8회뿐이라
(1,000건씩 7,329건) 개발계정 하루 한도 10,000회에 비하면 무시할 수준이고,
따로 캐시를 두는 것보다 매번 새로 받는 쪽이 단순하고 고장날 데가 적다.

## 실패했을 때

- **시크릿 없음** → Actions 로그에 어떤 키가 없는지 표시된다
- **인증키 거부** → 활용신청 승인 상태 확인. `collect_standard.py`는 Encoding/Decoding 두 형태를 모두 시도한다
- **안전장치 중단** → 수집 건수가 급감한 것이다. 먼저 원인을 보고, 의도한 축소면 `min_ratio`를 낮춰 재실행
- **커밋 없음** → 데이터가 그대로면 정상이다. "변경 없음 — 커밋 건너뜀"이 찍힌다
