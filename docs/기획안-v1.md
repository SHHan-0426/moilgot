## 1. 먼저 답 — 수도권만 하면 가능한가

**가능성이 크게 올라간다. 수도권으로 좁히는 것을 권한다.**

전국과 수도권은 데이터 구조가 아예 다르다.

| | 전국 | 수도권 3개 시도 |
|---|---|---|
| 소스 개수 | 251개 기관이 제각각 | **3개 광역 통합 시스템** |
| 갱신 | 분기(3개월) | **일 단위 이하** |
| 예약 상태 | 없음 | **있음** |
| 유지보수 | 사실상 불가능 | 파이프라인 3개 |

확인된 수도권 소스:

- **서울** — 서울시 공공서비스예약(`yeyak.seoul.go.kr`) + 공공서비스예약 종합 API. **매일 1회 갱신**, 서비스 상태(접수중/마감) 제공, `rsv_svc_id` 쿼리스트링으로 **예약 페이지 딥링크**. 시·자치구·산하기관 포괄.
- **경기** — **경기공유서비스**(`share.gg.go.kr`) 광역 공유자원 포털 + 경기데이터드림 **`경기공유서비스_시설대관` Open API**.
- **인천** — **인천 온라인통합예약**(`incheon.go.kr/res`) + 공공데이터포털 **`인천광역시_통합예약안내` API**. **예약 신청 시작·종료일, 운영 일자, 예약 그룹 구분코드** 제공. 활용신청 935건(검증된 API). **개발단계 자동승인** — 오늘 바로 키 받아 테스트 가능.

전국 백본이던 **전국공공시설개방정보표준데이터**(251개 기관·25개 항목·**분기 갱신**)는 수도권에서도 여전히 유용하다. 유료사용여부·사용료·사용기준시간·초과사용료·수용가능인원수·면적·부대시설·운영시간·신청방법·위도·경도까지 다 있다. 다만 **빈자리 정보는 없다.**

**대신 정직하게 말해둘 것 두 가지:**

1. **"시간대별 실시간 잔여"까지는 아직 미확정.** 세 API가 주는 건 접수 기간·운영 일자·상태값까지일 가능성이 높다. 시간대 단위 빈자리는 인증키 받고 실호출해야 확정된다 → Phase 0 과제.
2. **광역 시스템은 시·도 산하 시설 중심.** 수원시·성남시 등 시군구 자체 예약 시스템은 별도다. 수도권이라고 100%는 아니다.

**그럼에도 수도권 권장 이유**: 범위를 절반으로 줄이는 게 아니라, **유지비를 1/80로 줄이면서 수요의 절반을 잡는 것**이다. 수도권에 전국 인구 약 절반이 산다.

## 2. 문제 — 장소 구하기가 모임의 병목이다

소모임 운영자가 모임 하나를 잡을 때 실제로 하는 일:

1. 공유누리·지자체 사이트·블로그를 돌며 후보를 모은다
2. 각각 들어가 **무료인지 / 자격이 되는지 / 인원이 맞는지**를 따로 확인한다
3. 그날 비었는지는 결국 **전화**로 묻는다
4. 사이트마다 회원가입을 다시 한다

**삼중 확인 지옥**이다. 정보가 없어서가 아니라 **흩어져 있고, 조건으로 좁힐 수 없고, 신선도를 알 수 없어서** 생기는 문제다.

공유누리가 이미 있는데 왜 또 만드나 — 공유누리는 **자원 카탈로그**다. 유·무료가 섞여 있고 "우리 모임 조건에 맞는 곳"으로 좁히는 도구가 아니다. 이 사이트는 **모임 하나를 성사시키는 도구**다.

## 4. 척추 — 3단계 신선도 모델

수도권으로 좁혀도 모든 공간을 A층으로 만들 수는 없다. 그래서 층을 나누고 **화면에 층을 명시**한다.

| 층 | 무엇을 아는가 | 소스 | 갱신 | 화면 |
|---|---|---|---|---|
| **A. 예약 가능 확인됨** | 그 날짜에 비었는지 | 서울 yeyak · 경기공유 · 인천통합예약 | 실시간~1일 | 🟢 `8/29(토) 예약 가능` + **[예약하기]** |
| **B. 접수 중** | 지금 신청을 받는지 | 위 API 상태값·접수기간 | 1일 | 🟡 `접수 중 · 날짜는 확인 필요` + **[예약 페이지]** |
| **C. 시설 정보만** | 조건·요금·연락처 | 전국 표준데이터 | 분기 | ⚪ `전화로 확인` + **[전화 걸기]** + `최종 확인 2026.7.1` |

**절대 원칙: 모르는 걸 아는 척하지 않는다.**
C층을 A층처럼 보이게 하는 순간, 한 번 헛걸음시키고 신뢰를 잃는다. 배지가 이 사이트의 전부다.

부수 효과 — C층이 많아도 사이트는 여전히 유용하다. **조건으로 좁힌 전화 후보 5곳**이, 좁히지 못한 500곳보다 낫기 때문이다.

## 5. 화면 설계 (v1)

### 검색 = 첫 화면

입력은 **4개만**. 그 이상 v1에서 받지 않는다.

- **어디서** — 시·군·구 (현재 위치 버튼)
- **몇 명** — 인원
- **언제** — 날짜 (선택 안 하면 전체)
- **무엇을** — 회의 / 강의 / 모임·행사 / 운동

### 결과 카드

```
┌──────────────────────────────────┐
│ 🟢 8/29(토) 예약 가능            │
│ 화정도서관 다목적실         무료 │
│ 정원 20명 · 2.1km · 09~18시      │
│ 빔프로젝터 · 화이트보드          │
│                   [ 예약하기 ]   │
└──────────────────────────────────┘
```

정렬: **① 예약 가능 확인 → ② 무료 → ③ 가까운 순**

### 상세

사용료 계산기(기준시간 + 초과단위 요금 → "2시간이면 0원 / 6시간이면 6,000원") · 부대시설 · 신청방법 · 지도 · 원문 링크 · **[정보가 달라요] 신고 버튼**

### 지역 랜딩 페이지

`/고양시/무료-회의실` 형태 자동 생성. "고양시 무료 회의실 대관"이 실제 검색 수요다. **사이트 성패의 절반이 여기서 갈린다.**

## 6. 만들지 않는 것 (v1 제외)

- **자체 예약·결제** — 예약은 원 시스템으로 보낸다. 유지비 0, 법적 책임 0. 이 선을 넘는 순간 사업이 된다.
- **회원가입·로그인** — v1은 비로그인. 저장은 브라우저에.
- **후기·평점** — 데이터 없이 시작하면 빈 화면만 남는다. 이용자 생긴 뒤.
- **앱** — 모바일 웹으로 충분.

## 7. 기술 구조

검증된 `오늘 뭐하지` / `공모 한눈에` 패턴을 그대로 재사용한다.

```
서울 공공서비스예약 API (일 1회)  ┐
경기공유서비스 시설대관 API       ├→ GitHub Actions 매일 새벽 수집
인천 통합예약안내 API             │
전국 표준데이터 (분기)            ┘        ↓
                          정규화 · 시군구 코드 매칭 · 중복 제거
                                          ↓
                     시도별 분할 JSON 커밋 → Netlify 자동 배포
                                          ↓
                     정적 사이트 + 클라이언트 검색
                     (실시간 조회분만 Netlify Function 1개로 프록시)
```

- 검색은 클라이언트에서. **시·도 단위 JSON 분할 로드**
- API 키는 Netlify 환경변수 + Function 프록시 (클라이언트 노출 금지)
- 지도는 v1 후순위. 목록 + 거리 표시로 시작

**최대 리스크는 화려한 기능이 아니라 데이터 정규화다.** 주소 표기 제각각, 사용료가 자유 텍스트, 시설명 중복 — 여기서 시간이 다 간다.

## 8. 단계

### Phase 0 — 데이터 실사 (1주) · **이걸 하기 전엔 아무것도 만들지 않는다**

1. **인천 통합예약안내 API 키 발급**(개발단계 자동승인) → 오늘 바로 실호출
2. 서울 공공서비스예약 API 실호출 → 필드·상태값 확인
3. 경기데이터드림 시설대관 API 키 신청 → 필드 확인
4. 전국 표준데이터 다운로드 → **수도권만 필터**
5. 세어본다: 전체 / **무료 몇 건** / 실비 몇 건 / 시군구 커버리지 / 좌표 있는 비율 / 수용인원 채워진 비율
6. **핵심 확인**: 세 API가 **날짜 단위 예약 가능 여부**를 주는가, 아니면 접수 기간까지만 주는가

**판단 게이트** — 수도권 무료+실비 유효 건수가 1,500건 미만이면 범위를 **서울+경기 남부**로 더 좁힌다.

### Phase 1 — 검색 MVP (2주)
서울 1개 시도로 좁혀 검색 → 결과 → 상세 → 예약/전화까지 한 흐름 완성. 배지 시스템 포함.

### Phase 2 — 수도권 확대 + 지역 랜딩 (2주)
경기·인천 파이프라인 붙이고 지역 랜딩 자동 생성, 검색엔진 노출, 신고 버튼 운영.

### Phase 3 — 정밀도 (이후)
공유누리 OPEN API(승인제) 추가, 시군구 자체 시스템 개별 연동, 지도 뷰.

## 10. 리스크

| 리스크 | 대응 |
|---|---|
| 분기 갱신 → 폐관·요금 변경 시차 | `최종 확인일` 항상 표기 + 신고 버튼 + 전화번호 병기 |
| API가 날짜 단위 빈자리를 안 줄 경우 | A층 없이 B·C층만으로도 사이트가 성립하도록 설계 (이미 그렇게 잡음) |
| 시군구 자체 시스템 누락 | 커버리지를 숨기지 않고 "이 지역은 OO곳 수록" 명시 |
| 데이터 품질(주소·요금 자유텍스트) | Phase 0 실측 후 범위 조정 |
| 공유누리와 뭐가 다르냐 | 무료·실비만 / 조건으로 좁힘 / 신선도 명시 / 중장년 가독성 |
